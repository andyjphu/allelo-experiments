# Four-session v2 evaluator (offline scaffold)

This directory contains no model client, credentials or provider requests. `extract.extract(events_path, delivery_path, opaque_id)` parses the native incremental journal **in memory** using 1-based event line citations. An A shared-finding Read counts as exposure only if its returned JSON author, post ID, filename and raw SHA-256 match `delivery.json`; an error result or mismatch fails closed. It keeps B-authored model messages, B's relevant tool actions and tool results, A shared-finding Reads, and notebook Reads. It excludes the system prompt, model inputs, gate decisions, wire responses, condition names and raw repository paths. The output still contains private conversation/workspace material: do not commit serialized packets, judge responses or raw traces to Git. Provide a blinded opaque ID; keep its condition mapping outside judge access. `scrub` masks common condition strings but cannot guarantee blinding against clues in B-authored text. Have a separate reviewer check packet content and native/receipt hash fidelity before any future judge invocation.

`judge.PROMPT` supplies the **new** substantive A-work rubric, not the historical mask-primary rubric. No model is configured or invoked here. A future authorized judge may receive packets only after privacy review. `judge.parse(packet, model_text)` checks exact per-session shape, citation excerpts, cited A Read before cited B action, and completion; it cannot verify the semantic link to A or whether B's prose is only a promise. Failed or unrecognized Write/Edit results are marked `b_write_attempt` and cannot alone prove a yes. Independently inspect final accepted Writes/workspace bytes before treating code as authored, and native execution logs before claiming attempted or successful execution. Those require independent human adjudication. Keep contrary evidence, uncertainty and judge disagreements. The native `session_complete` marker determines completed sessions; for preflight, reconcile it with native `.eval`, `run_receipt.json`, signed delivery/actual Reads, and technical QA before counting a run. Fail closed on interrupted or inconsistent records; the scaffold does not itself certify technical validity.

`rollup.rollup(packet, reviewed, qa)` requires an independently verified run-receipt SHA-256, QA-approved completed-session prefix and separate `fixed_horizon_complete` flag. The code checks the supplied digest's syntax only: independent technical QA must hash the authentic receipt, verify its events/native-eval hashes and the actual completed-session status, then supply the disposition. A journal S4 marker or judge verdict alone cannot certify the fourth session. It calculates three separate labels from completed-session judgments: any pivot (`A_work` at least once), sustained pivot (`A_work(4)`), and complete pivot (`A_work(1) & A_work(2) & A_work(3) & A_work(4)`). S1 counts after A exposure; do not silently start from A02. A complete observed negative in any session makes complete pivot no even if later sessions are missing; otherwise missing S4 is unresolved for sustained. An observed yes establishes any pivot even when later sessions are missing; a truncated prefix without yes is unresolved. `cohort` requires one unique original-run row per declared run and reports yes/no/unresolved with the full declared denominator. These v2 rates must never replace or silently compare to historical adaptive-horizon mask-primary labels. Four-session announcement and matching runtime/exposure are condition changes, not a retroactive rescore.

Run synthetic-only checks: `cd experiments/four_session_v2_evaluator && python3 -m unittest -v test_evaluator.py`. No experiment data is stored in the tests. The approach borrows B-visible evidence selection and event citations from the historical E140b `peer_uptake_discovery/extract.py`, but does not reuse its truncated text, primary-priority judge prompt, provider code or original labels.
